**bcli v0.14.0** is the first final public release of the command-line client for [servas.ai](https://servas.ai)
Browser as a Service: real, headed cloud browsers for your agents and tests, driven over standard CDP, for
**Linux, macOS and Windows**. Install it from the terminal with one command; the installers check the release
signature first.

## Highlights

- **Install from the terminal:** `install.sh` (Linux, macOS) and `install.ps1` (Windows) verify the Ed25519 signature
  of `SHA256SUMS` and the SHA-256 of the binary before they install. Also available through Homebrew and Scoop.
- **Windows client:** per-user install without administrator rights, local daemon, local vault in the background,
  Edge sessions with the credential extension, cloud sessions with `vault unlock --session`, Bitwarden bridge with a
  native approval dialog, logon start (`bcli daemon autostart enable [--bwbridge]`), signed self-update
  (`bcli update`) and `bcli uninstall [--purge]`.
- **macOS on Apple silicon and Intel:** full CLI with the native approval dialog and the Bitwarden bridge, now also
  for Intel Macs (`bcli-darwin-amd64`).
- **Several Bitwarden vaults in one approval window:** `bcli vault bw setup --add` adds another vault to the same
  bridge; matching logins are grouped by vault label and account.
- **OIDC sign-in** via `auth.servas.ai` (`bcli login`): no VPN, no API keys.
- **One command to a real browser:** `bcli session create --wait`, then `connectOverCDP(cdp_url)`, then
  `bcli session stop`. Live view and hand-over, persistent profiles, your own exit IP, localhost tunnels, GPU sessions.
- **Agent-ready:** the `agent-web` helper (bash + PowerShell), a Claude Code skill and an `AGENTS.md` snippet in this
  repository.

## Install

```bash
# Linux and macOS
curl -fsSL https://raw.githubusercontent.com/servas-ai/bcli-public/main/install.sh | sh
```

```powershell
# Windows (normal PowerShell window)
irm https://raw.githubusercontent.com/servas-ai/bcli-public/main/install.ps1 | iex
```

Homebrew: `brew install servas-ai/tap/bcli`. Scoop: `scoop bucket add servas https://github.com/servas-ai/scoop-bucket`,
then `scoop install servas/bcli` (Scoop needs `scoop install git` once). winget: `servas.bcli` is submitted
([winget-pkgs#486222](https://github.com/microsoft/winget-pkgs/pull/486222)). Pin this release with `sh -s -- --version v0.14.0` or `$env:BCLI_VERSION = "v0.14.0"`.
Everything else: [docs/installation.md](https://github.com/servas-ai/bcli-public/blob/main/docs/installation.md).

## Verify

The install scripts do this for you. By hand: `SHA256SUMS.sig` is the Ed25519 signature of `SHA256SUMS` with the
servas.ai CLI release key
([keys/bcli-release-ed25519.pem](https://github.com/servas-ai/bcli-public/blob/main/keys/bcli-release-ed25519.pem));
check it with OpenSSL 3 or, on Windows, with
[scripts/windows/verify-release.ps1](https://github.com/servas-ai/bcli-public/blob/main/scripts/windows/verify-release.ps1),
then check the binary against `SHA256SUMS`
([how](https://github.com/servas-ai/bcli-public/blob/main/docs/installation.md#verify-the-signature-of-sha256sums)).

## Get started

```bash
bcli env add cloud --kind cloud --endpoint https://api.baas.servas.ai && bcli env use cloud
bcli login
bcli session create --wait
```

## Known limitations

- **No code signing, by design.** bcli has no Windows Authenticode signature and no Apple Developer ID or
  notarization; the Ed25519 signature is what counts. Installed from the terminal or a package manager, bcli starts
  without a Windows or macOS prompt. **Machines that only allow signed programs** (AppLocker, App Control for
  Business / WDAC, Smart App Control) are not supported.
- **Windows:** `bcli assist` and `bcli audio` are not available; use the live view for human hand-over. Daemon, vault
  and Bitwarden bridge run only from non-elevated terminals in your logon session, not from a scheduled task. Edge
  shows a "Disable developer mode extensions" pop-up for local sessions; close it with the ×.
- **Windows known issues** (fixed in a later patch release): the first `bcli vault bw autofill` a few seconds after a
  new local session opened its page can fail once with `bw: bridge operation failed`, running it again works; the
  passphrase file `vault.passphrase` is ignored without a message unless its ACL is owner-only (workaround in
  [the install guide](https://github.com/servas-ai/bcli-public/blob/main/docs/installation.md#the-vault-in-the-background)).
- **macOS Intel:** cloud sessions work; the LaunchAgent helper for local mode supports Apple silicon only in this
  release.
- **Local mode on Linux and macOS** needs `browser_path` / `BAAS_BROWSER_PATH` pointing to a Chromium-based browser.
