**bcli v0.14.6** makes local autofill work in **Google Chrome**, picks a browser for local sessions by itself on
Linux and macOS, and fixes the Bitwarden approval window on Debian and Ubuntu machines whose `~/.cache` is shared
with the user's own group. Same platforms, same install paths; `bcli update` brings it to an existing install.

## Changes

- **Google Chrome works for local sessions.** Chrome 137 and newer ignore `--load-extension`, so bcli's credential
  extension never started there and `bcli vault bw autofill` ended with "browser extension not connected yet". bcli
  now loads the extension into Google Chrome over a private DevTools pipe; Chromium, CloakBrowser and Edge keep the
  old way. Brave is not supported (it looks for bcli's native-messaging registration in Chrome's folder).
- **Browser choice on Linux and macOS:** without `BAAS_BROWSER_PATH` or `browser_path`, bcli picks CloakBrowser,
  Chromium, Google Chrome or Microsoft Edge itself. `bcli daemon status` shows the browser it uses.
- **macOS: `bcli daemon start` installs the daemon's LaunchAgent** (`ai.servas.bcli.daemon`) like
  `bcli bwbridge start` does for the bridge; `scripts/macos/install-macos.sh` is no longer needed.
- **Bitwarden approval window with `~/.cache` mode 0775** (Debian/Ubuntu with umask 002): the window now opens;
  bcli keeps only its own folder `~/.cache/bcli` private. If other users really could change the cache folder, or
  `~/.cache/bcli` belongs to another user (e.g. after `sudo bcli`), the error names the cause and the fix instead of
  "bridge operation failed".
- **Clearer messages:** a closed or cancelled Bitwarden window says so; a bridge without a display (started over SSH,
  WebKitGTK missing, macOS outside the login session) says what to do. Guide:
  [docs/bitwarden.md](https://github.com/servas-ai/bcli-public/blob/main/docs/bitwarden.md#troubleshooting).

## Install

```bash
# Linux and macOS (in a terminal of your desktop session, so the Bitwarden bridge is set up too)
curl -fsSL https://raw.githubusercontent.com/servas-ai/bcli-public/main/install.sh | sh
```

```powershell
# Windows (normal PowerShell window)
irm https://raw.githubusercontent.com/servas-ai/bcli-public/main/install.ps1 | iex
```

Already installed: `bcli update` (or `brew upgrade bcli`, `scoop update bcli`), then on Linux and macOS
`bcli bwbridge start --restart` once, so the running bridge uses the new version. Homebrew:
`brew install servas-ai/tap/bcli`. Scoop: `scoop bucket add servas https://github.com/servas-ai/scoop-bucket`, then
`scoop install servas/bcli`. Pin this release with `sh -s -- --version v0.14.6` or `$env:BCLI_VERSION = "v0.14.6"`.
Everything else: [docs/installation.md](https://github.com/servas-ai/bcli-public/blob/main/docs/installation.md).

## Verify

The install scripts do this for you. By hand: `SHA256SUMS.sig` is the Ed25519 signature of `SHA256SUMS` with the
servas.ai CLI release key
([keys/bcli-release-ed25519.pem](https://github.com/servas-ai/bcli-public/blob/main/keys/bcli-release-ed25519.pem));
check it with OpenSSL 3 or, on Windows, with
[scripts/windows/verify-release.ps1](https://github.com/servas-ai/bcli-public/blob/main/scripts/windows/verify-release.ps1),
then check the binary against `SHA256SUMS`
([how](https://github.com/servas-ai/bcli-public/blob/main/docs/installation.md#verify-the-signature-of-sha256sums)).

## Known limitations

- macOS: local sessions and the Bitwarden window are built and unit-tested; the full check on a Mac is still open.
- Brave is not supported for local sessions.
- Unchanged from [v0.14.0](https://github.com/servas-ai/bcli-public/releases/tag/v0.14.0): no code signing by design
  (the Ed25519 signature is what counts), `bcli assist` and `bcli audio` are not available on Windows, local mode on
  macOS needs Apple silicon.
